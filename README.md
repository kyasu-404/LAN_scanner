# LAN Scanner

Интерактивный сканер IPv4-сетей на Python. Использует Nmap для обнаружения хостов, проверки TCP-портов и определения сервисов и ОС. Показывает результаты в терминале и сохраняет их в CSV, JSON или HTML.

## Установка

Установите Python 3.10+ и Nmap. Добавьте Nmap в `PATH`. На Windows при установке Nmap оставьте включённым Npcap и затем откройте новый терминал. [Загрузить Nmap](https://nmap.org/download.html)

**Windows**

```powershell
py -m pip install rich
py LAN_scaner.py
```

**Linux и macOS**

```bash
python3 -m pip install rich
python3 LAN_scaner.py
```

Если системный Python запрещает установку через pip, установите `rich` в виртуальном окружении и запускайте сканер в нём. Для определения ОС на Windows запустите терминал от имени администратора. В Linux и macOS запускайте сканер с правами, необходимыми Nmap для работы с сырыми пакетами. Для обычного сканирования Nmap сам выбирает подходящий тип TCP-проверки. [Документация Nmap](https://nmap.org/book/man-port-scanning-techniques.html)

## Режимы

| Профиль | Какие TCP-порты проверяет | Версии сервисов по умолчанию | Лимит Nmap на хост |
| --- | --- | --- | --- |
| FAST | 100 наиболее распространённых | Выключено | 90 с |
| BALANCED | 1 000 наиболее распространённых | Включено | 180 с |
| FULL | Все 65 535 | Включено | 900 с |

Для сканирования подсети введите IPv4-сеть в CIDR, например `192.168.1.0/24`. Список вроде `22,80,443,8000-8010` заменяет набор портов выбранного профиля. Определение версий и ОС настраивается отдельно. Сканер сначала обнаруживает хосты, затем передаёт их Nmap группами. Размер группы можно выбрать от 1 до 256 адресов, по умолчанию 32. Nmap сам управляет параллелизмом внутри группы.

**Deep Scan** доступен из главного меню и после сканирования подсети. Для одного IPv4 он проверяет все TCP-порты и определяет версии сервисов. Определение ОС можно включить при наличии необходимых прав. Отчёт Deep Scan сохраняется отдельно.

## VLAN, ARP и MAC-адреса

Для целей в локальном сегменте Nmap использует ARP, если интерфейс и права позволяют отправлять такие запросы. ARP работает внутри одного L2-сегмента. Маршрутизация между VLAN даёт IP-доступ, но не переносит ARP-запросы в соседний VLAN. При сканировании через маршрутизатор Nmap использует IP-проверки доступности. Межсетевые экраны могут отфильтровать эти проверки, а MAC-адрес и производитель удалённого устройства, как правило, останутся пустыми. Чтобы получить MAC-адреса хостов конкретного VLAN, запустите сканер из этого VLAN. [Документация Nmap об обнаружении хостов](https://nmap.org/book/man-host-discovery.html)

## Отчёты

Терминал и все форматы экспорта показывают открытые порты, сервисы и доступные версии. Файлы сохраняются в текущем каталоге под именами `scan_results.*` и `deep_scan_results.*`. В CSV каждому открытому порту соответствует строка. Если по хосту портов нет, CSV всё равно содержит строку с данными хоста. В JSON порты вложены в запись хоста. Указанный тип устройства является предположением, рядом выводятся признаки. При противоречивых или недостаточных признаках тип остаётся `Unknown`.

| Статус | Значение |
| --- | --- |
| `ok` | Nmap завершил проверку хоста и вернул его запись. |
| `partial` | Nmap вернул запись хоста, но запуск завершился с ошибкой или по тайм-ауту. |
| `no_response` | Хост не ответил на обнаружение либо Nmap не вернул его запись. |
| `timeout` | Истёк лимит времени для хоста или группы без результата по этому адресу. |
| `error` | Ошибка запуска, сканирования или разбора результата. |

При ошибке отдельного запуска сканер сохраняет доступные данные и показывает диагностику. Пустой список портов при статусе `partial`, `timeout` или `error` означает, что полноценный результат по портам не получен.

## Проверки

`python -m unittest -v` запускает проверки на тестовых XML-данных без обращения к сети.
